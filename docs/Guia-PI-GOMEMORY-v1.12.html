Qué es pi-gomemory

Pi es rápido y extensible. Lo que le falta es memoria, mapa del código y un método de trabajo.

Pi arranca cada sesión desde cero. No sabe qué decidiste ayer, qué bug ya corregiste ni qué módulo llama a cuál. Para cada pregunta sobre el código abre archivos uno tras otro, y cuando termina una tarea nada le obliga a demostrar que funciona.

Arreglarlo a mano lleva una tarde: registrar tres servidores MCP en mcp.json, copiar y corregir una veintena de skills, instalar dos plugins de npm, ajustar el tema y escribir un script que cargue el contexto del proyecto antes de abrir Pi. Es fácil dejar algo a medias, y en la siguiente máquina hay que repetirlo.

pi-gomemory hace ese montaje con un comando. Lleva sus recursos (skills, tema, extensiones y configuración) dentro del ejecutable con embed.FS, así que no descarga nada durante la instalación y deja el mismo resultado en cualquier equipo.

Las capas del harness

Lo que queda alrededor del modelo cuando terminas de instalar

Memoria
gomemory guarda decisiones, bugs con su causa raíz y convenciones, y las devuelve al empezar cada sesión.
Grafo de código
CodeGraph y codebase-memory-mcp responden quién llama a qué y qué se rompe si cambias algo, sin recorrer carpetas.
Método
El protocolo HCD y 21 skills llevan un cambio de la intención al cierre, con la prueba en rojo antes que en verde.
Interfaz
Banner, modo plan, tareas, panel lateral, inspector de pruebas y barra de tokens, con el tema gomemory en Truecolor.

Cómo encaja todo

install.sh→ verifica SHA256→ pi-gomemory-setup→ ~/.pi/agent · ~/.pi-gomemory/skills→ ~/.local/bin/pi-gomemory→ Pi con memoria y grafo

Hay dos ejecutables y conviene no confundirlos. pi-gomemory-setup es el binario en Go que instala, diagnostica, actualiza y desinstala. pi-gomemory es un script de bash que el instalador genera; lo usas cada día para abrir Pi.

Alcance

pi-gomemory configura solo Pi. Si también usas Claude Code, Codex, Antigravity u OpenCode, la memoria y los grafos les llegan a través de gomemory con mem setup-mcp. El capítulo 15 lo explica.

Instalar, paso a paso

Tres caminos que terminan igual: el binario en ~/.local/bin y el harness montado.

  1. Ejecuta el script de instalación recomendado

    Descarga el binario de tu plataforma desde GitHub Releases, comprueba su SHA256 contra SHA256SUMS y lanza la instalación completa. Si la suma no coincide, se detiene.

    bash
    curl -fsSL https://raw.githubusercontent.com/Sayoner-000/pi-gomemory/main/install.sh | bash

    pi-gomemory-setup queda en ~/.local/bin y el resumen de la instalación termina sin errores.

  2. O compila desde el código fuente

    Útil si quieres revisar el código antes de ejecutarlo. Compila sin símbolos de depuración, copia el binario y ejecuta el instalador.

    bash
    git clone https://github.com/Sayoner-000/pi-gomemory.git
cd pi-gomemory
make install

  3. O descarga el binario a mano

    Para máquinas sin acceso directo a GitHub o cuando prefieres verificar cada paso. Elige el tarball de tu sistema: darwin_arm64, darwin_amd64, linux_amd64 o linux_arm64.

    bash
    shasum -a 256 -c SHA256SUMS --ignore-missing
tar -xzf pi-gomemory-setup_v1.12.1_darwin_arm64.tar.gz
mkdir -p ~/.local/bin
mv pi-gomemory-setup ~/.local/bin/
pi-gomemory-setup install

  4. Comprueba el resultado con doctor

    Revisa binarios, tema, servidores MCP, plugins, skills, extensiones y launcher. Cada línea dice qué falta y, si aplica, qué comando lo arregla.

    salida esperada (resumida)
    pi-gomemory-setup doctor

  ✓ Binario pi                       /Users/usuario/.local/bin/pi
  ✓ Binario mem                      /Users/usuario/.local/bin/mem
  ✓ Tema gomemory en Pi              ~/.pi/agent/themes/gomemory.json
  ✓ MCP gomemory                     conectado
  ✓ MCP codegraph                    conectado
  ✓ MCP codebase-memory              conectado
  ✓ Plugin pi-antigravity (Google)   registrado en settings.json
  ✓ Skills gomemory en Pi            21 skills cargadas
  ✓ Launcher Herdr (pi-gomemory)     ~/.local/bin/pi-gomemory

    todas las líneas en verde, o una lista corta de piezas opcionales pendientes.

  5. Abre Pi con el launcher

    Desde la carpeta de tu proyecto. Si ahí hay una memoria de gomemory (.gomemory/memories.db), Pi empieza con el contexto del proyecto. Si es la primera vez, ejecuta antes mem init.

    bash
    cd ~/mi-proyecto
pi-gomemory

    el banner muestra la gota de gomemory con las versiones de pi-gomemory y de gomemory.

Variables de install.sh

PI_GOMEMORY_VERSION fija una versión concreta, PI_GOMEMORY_BIN_DIR cambia la carpeta de destino y PI_GOMEMORY_BASE_URL apunta a otra fuente de descarga, por ejemplo file://$PWD/dist para probar un build local.

Cómo fusiona

mcp.json
Solo cambia sus tres entradas. Tus otros servidores se quedan como estaban, con todos sus campos.
pi-cc-extensions.json
Añade las claves que falten. Lo que ya ajustaste se respeta, con una excepción: fija showStartupHeader: false para que no tape el banner.
AGENTS.md
El protocolo vive entre <!-- pi-gomemory:start --> y <!-- pi-gomemory:end -->. Reinstalar reemplaza ese bloque y deja el resto del archivo intacto.
JSON inválido
Si encuentra un JSON existente que no puede leer, la instalación se detiene y no lo modifica. Corrige el archivo y vuelve a ejecutar.
Lo que nunca toca

El directorio desde el que lo ejecutas, la configuración de otros agentes, las skills de ~/.claude/skills y compañía (las enlaza, no las copia) y la memoria de gomemory.

El launcher

pi-gomemory hace cinco cosas antes de ceder el control a Pi.

El launcher es un script corto con set -euo pipefail. Lo puedes leer en ~/.local/bin/pi-gomemory; esto es lo que hace, en orden.

  1. Prepara la terminal

    Exporta HERDR_ENV=1, COLORTERM=truecolor, GOMEMORY_CLIENT=pi y pone por delante en el PATH su propia carpeta, ~/.local/bin y ~/.gomemory/bin. Respeta los valores que ya tengas definidos.

  2. Atiende usage

    Si el primer argumento es usage o quota, delega en pi-gomemory-setup usage y muestra la cuota de Google AI Pro sin abrir Pi.

  3. Revisa versiones

    Exporta PI_GOMEMORY_RUNNING_VERSION y GOMEMORY_INSTALLED_VERSION para el banner. Después ejecuta deps-status con el resultado de la consulta anterior; si algo está desactualizado y hay terminal interactiva, pregunta ¿Actualizar ahora? [s/N] durante 10 segundos. La consulta nueva se lanza en segundo plano y no retrasa el arranque.

  4. Sincroniza las skills

    Ejecuta skills-sync, que solo crea o retira enlaces en ~/.pi-gomemory/skills. Es rápido y silencioso.

  5. Carga la memoria y abre Pi

    Si existe .gomemory/memories.db en la carpeta actual, ejecuta mem context y pasa el resultado con --append-system-prompt. Por encima de 64 KiB lo recorta para no superar el límite de argumentos del kernel. Termina con exec pi --use-theme gomemory y tus argumentos.

    Pi abre con el tema gomemory y, en un proyecto inicializado, con las decisiones recientes en el contexto.

uso habitual
# abrir Pi en el proyecto actual
pi-gomemory

# los argumentos pasan tal cual a pi
pi-gomemory --model anthropic/claude-sonnet-4-5

# ver la cuota de Google AI Pro sin abrir Pi
pi-gomemory usage

# arrancar sin comprobar actualizaciones
PI_GOMEMORY_NO_UPDATE_CHECK=1 pi-gomemory
Si abres pi directamente

Las extensiones, el tema y las skills siguen ahí, pero no hay contexto de gomemory al inicio ni comprobación de versiones, y el banner aparece sin números de versión. Para el trabajo diario, usa el launcher.

Memoria y grafos dentro de Pi

gomemory guarda el porqué. Los grafos responden el qué y el cómo.

Los tres servidores MCP aparecen en Pi como herramientas que el modelo puede llamar. El protocolo que el instalador escribe en AGENTS.md le dice cuándo usar cada una, y en qué orden.

ServidorComandoHerramientas que más se usan
gomemorymem mcpget_context, search_memories, save_memory, get_plan_context, review_*, end_session
codegraphcodegraph serve --mcpcodegraph_explore: devuelve el código de los símbolos relevantes y la ruta de llamadas entre ellos en una sola consulta
codebase-memorycodebase-memory-mcpsearch_graph, trace_path, get_code_snippet, check_index_coverage

El protocolo de AGENTS.md

Cinco reglas, más una para Splash

Buscar en la memoria
Para decisiones pasadas, search_memories o get_context. Nunca grep sobre el historial.
Grafo antes que grep
Arquitectura, rutas y relaciones van por codegraph_explore, search_graph o trace_path. Grep queda para literales, configs y archivos no indexados.
Guardar sin que lo pidan
Tras una decisión de arquitectura, un bug corregido con su causa raíz o una convención nueva, save_memory.
HCD y modo plan
Comprobar la unidad activa con mem hcd show, registrar evidencia con mem hcd verify y, para planificar, cargar get_plan_context y entregar el árbol de tareas sin ejecutar.
Pi de serie
  • Pregunta «¿quién llama a InstallSkills?» y abre archivos uno por uno.
  • Repite una decisión que ya se descartó la semana pasada.
  • Al cerrar la sesión, lo aprendido se pierde.
Pi con pi-gomemory
  • codegraph_explore devuelve los siete llamadores y sus tests en una llamada.
  • search_memories encuentra la decisión y su motivo.
  • save_memory y end_session dejan el resumen para la próxima vez.
Indexar el proyecto

Los grafos necesitan un índice. La primera vez, pide a Pi que indexe el repositorio (index_repository de codebase-memory) o ejecuta codegraph en la carpeta. gomemory indexa el código Go por su cuenta con mem.

El repositorio de skills

Una sola carpeta para Pi, sin colisiones de nombres.

Pi carga skills desde varias carpetas y avisa cada vez que dos se llaman igual. Si usas varios agentes, esas carpetas se solapan y el arranque se llena de advertencias. pi-gomemory registra en settings.json una única ruta, ~/.pi-gomemory/skills, y reúne ahí todo lo demás.

Las 21 de gomemory
Se copian adaptadas para Pi y siempre ganan. Cada copia lleva una marca .pi-gomemory con el SHA256 de su SKILL.md; si la editas, el instalador la deja en paz.
Las de otros agentes
Se enlazan con symlinks, en este orden: ~/.agents/skills, ~/.config/opencode/skills, ~/.claude/skills, ~/.codex/skills y ~/.gemini/skills. Si un nombre se repite, gana la primera carpeta.
GrupoSkills
HCDhcd, hcd-define, hcd-clarify, hcd-approve, hcd-slice, hcd-tasks, hcd-implement, hcd-verify, hcd-analyze, hcd-close
Rigorverify-loop, search-first, iterative-retrieval, strategic-compact, instincts, atomic-decomposition
Revisiónadversarial-consensus-review (ACR), defensive-qa-audit (ADM)
Memoria y apoyocodebase-memory, constitution, socratica

El modelo carga una skill cuando la tarea coincide con su descripción. Si quieres forzarla, escribe /skill:nombre en el editor de Pi, con argumentos si hace falta:

en Pi
/skill:hcd corregir el cálculo de cuota cuando la API devuelve 0
/skill:verify-loop
/skill:defensive-qa-audit pkg/installer
Sanitización

Pi lee el bloque YAML de cada SKILL.md con un analizador estricto. Una description: con dos puntos sin comillas hace que la skill no cargue. SanitizeFrontmatter detecta ese caso y envuelve el valor entre comillas antes de copiarlo.

bash
pi-gomemory-setup skills        # reúne de nuevo el repositorio y lo registra
pi-gomemory-setup skills-sync   # sincroniza enlaces y purga copias legadas
pi-gomemory-setup doctor        # muestra el total y las colisiones resueltas

Banner

Al abrir Pi verás la gota de gomemory, «pi - gomemory» y las dos versiones que exporta el launcher. Pi solo admite una cabecera, así que el instalador desactiva la de pi-cc-extensions. Si la vuelves a activar desde /ccstyle, doctor te avisa en la línea «Banner gomemory». Con NO_COLOR el banner se dibuja sin colores.

Modo plan

Con /plan Pi puede leer, buscar y razonar, pero no modificar. Bloquea las herramientas edit y write y los comandos de consola que cambian archivos: rm, mv, redirecciones, sed -i, git commit, npm install, go get y otros. Además añade al contexto el método de descomposición de mem plan-context y muestra «PLAN» en la barra.

en Pi
/plan añadir soporte de Windows al instalador
# … revisas el árbol de tareas que propone …
/plan run
Límite

Bloquea las modificaciones comunes, no aísla el proceso. La lista de patrones está en ~/.pi/agent/extensions/gomemory-plan-patterns.json y la puedes ampliar.

Panel de tareas

Encima del editor, /tasks muestra las tareas de la unidad HCD activa leídas de mem hcd show --json. Se actualiza al abrir la sesión, después de cada mem hcd y al terminar cada respuesta.

✓ verificada
La comprobación pasó y el código no ha cambiado desde entonces.
○ pendiente
Aún no tiene evidencia.
◌ caducada
Pasó, pero el código cambió después. Hay que volver a verificar.
✗ con fallo
La última comprobación falló.

Barra de tokens

/tokens alterna la barra inferior con los tokens de entrada y salida, las lecturas de caché (↺), el nivel de razonamiento ([thinking nivel]) y el coste estimado acumulado.

El panel lateral

Sesión, contexto, coste y cuotas, sin salir de la conversación.

/sidebar abre un panel de 36 columnas en la esquina superior derecha, inspirado en el de OpenCode. Flota sin capturar el teclado, así que puedes seguir escribiendo mientras está abierto.

Sesión y HCD
La unidad activa y la versión instalada en el título.
Contexto
Tokens usados, porcentaje de la ventana y coste, en tiempo real.
MCP
Los servidores declarados en mcp.json con estado Configured. No comprueba la conexión en vivo.

Cuotas

Google AI Pro
Porcentaje restante de los límites semanal y de cinco horas, y el tiempo hasta cada reinicio. También desde la terminal con pi-gomemory usage.
Anthropic · plan 1.11.0
Con Pi conectado por OAuth a una suscripción Claude Pro o Max, muestra el uso de la sesión (5 h) y de la semana, y los límites por modelo si Anthropic los envía. La barra pasa a amarillo al 50 % y a rojo al 80 %. Lee las cabeceras de las respuestas del modelo; solo consulta el endpoint como respaldo inicial, sin sondeo recurrente.
Errores a la vista

Si una consulta falla, el panel muestra el error completo y nunca cifras viejas o inventadas. Los dos casos habituales son el token caducado (abre pi para que lo renueve) y un binario anterior a 1.11.0 sin anthropic-usage (ejecuta pi-gomemory-setup update).

OpenAI Codex · nuevo en 1.12.0

Con el proveedor openai-codex activo y sesión OAuth de Pi, «▼ Codex Quota» muestra las ventanas primaria y secundaria, habitualmente cinco horas y semana. Las barras indican porcentaje restante; el JSON de codex-usage devuelve porcentaje usado. Lee auth.json y consulta wham/usage, sin renovar tokens.

Se consulta al abrir, con eventos de sesión/modelo/respuesta y con un heartbeat de 30 segundos mientras el panel está abierto. Los eventos fuerzan consultas adicionales; el intervalo no limita su frecuencia total. Sin sesión, con token caducado o error HTTP, se muestra un error en lugar de cifras anteriores.

Minimizar

  • Clic en [−] de la cabecera lo reduce a una fila; clic en [+] lo restaura. El ratón funciona en el modo fullscreen de Pi, que es el predeterminado.
  • /sidebar min (o /sidebar m, /sidebar -) hace lo mismo desde el teclado, también en --tui-mode regular.
  • /min actúa sobre los dos paneles: si alguno está expandido, minimiza ambos; si los dos están minimizados, los restaura.
  • En una terminal de menos de 100 columnas el panel se oculta solo.
las mismas cifras en JSON
pi-gomemory-setup usage --json       # Google AI Pro
pi-gomemory-setup anthropic-usage    # sesión y semana del plan de Anthropic
pi-gomemory-setup claude-usage       # tokens de Claude Code: hoy, semana y total
pi-gomemory-setup codex-usage        # porcentaje usado y reinicios de OpenAI Codex

Pruebas en vivo con /tdd

Las pruebas reales del proyecto, test a test, con cada fallo de vuelta al agente.

/tdd abre el TDD Live Inspector debajo del panel lateral, en la misma columna. Detecta qué suites tiene sentido ejecutar en el proyecto abierto y las lanza.

Resultados fiables desde v1.12.1

Interrupciones y timeouts se cierran como fallos con su causa, cada prueba Playwright se identifica por proyecto y su estado sale del informe JSON oficial, y las recuperadas en un reintento se cuentan como flaky. Las versiones anteriores y sus mitigaciones están en problemas conocidos.

Una suite que no aplica, o cuya herramienta falta, aparece como «omitida» con el motivo. Nunca cuenta como éxito ni como fallo, y las omitidas se agrupan al final.

Qué ves mientras corre

Los procesos se lanzan con spawn, sin shell, y la salida se lee línea a línea. Por eso el panel avanza mientras los tests se ejecutan: los que están en curso llevan el spinner braille de Pi, los aprobados se resumen en un conteo (✓ 108 aprobados) y cada fallo (✗) trae su archivo y línea, el paso de Playwright si lo hay, el mensaje real (por ejemplo Expected 13 · Received 7) y un diagnóstico.

SubcomandoEfecto
/tddMuestra u oculta el panel y lanza todas las suites.
/tdd run [suite]all, backend, frontend, playwright, ci o data. Si ya hay una ejecución en curso, la nueva queda en cola.
/tdd minMinimiza o restaura el inspector (también /tdd m, /tdd - o clic en [−]).
/tdd watchEjecuta las pruebas una vez cuando el agente termina el prompt, solo si cambió archivos (edit, write o bash). No bloquea al agente ni se dispara en prompts de solo lectura.
/tdd reportPublica en el chat el informe de la última ejecución, con cada fallo. Queda en el contexto del modelo sin iniciar un turno.

El bucle con el agente

El modelo tiene su propia herramienta, run_test_suite. Devuelve cada fallo con suite, test, mensaje, ubicación, paso, diagnóstico y sugerencia, y envía avances mientras corre. Así Pi puede ejecutar, leer el fallo, corregir y volver a ejecutar sin que copies nada.

/tdd run backend→ ✗ 2 fallos→ /tdd report→ «corrige esos fallos»→ run_test_suite→ ✓ verde

HCD dentro de Pi

Cada cambio es una unidad con intención, tareas, evidencia y un cierre aprobado.

HCD (Harness Continual Development) es el protocolo de gomemory para llevar un cambio de la idea al cierre. El motor es mem hcd; las skills hcd-* lo conducen desde Pi, y la terminal queda como vía de respaldo.

Dos carriles

Vía rápida --lane fast
Para fixes y cambios acotados.
/hcd→define→tasks→implement→verify→close
Ceremonia completa --lane full
Para features y cambios con riesgo. Añade aclaraciones, aprobación citada de la definición y división en incrementos.
define→clarify→approve→slice→tasks→…

Desde Pi

Lo normal es pedirlo en lenguaje natural o forzar la skill de entrada. /skill:hcd elige el carril, crea o retoma la unidad y te dice el paso siguiente.

en Pi
/skill:hcd el panel lateral no muestra el error cuando el token caducó
# Pi crea la unidad, redacta la definición y propone las tareas
/tasks
# ○ 1 prueba que reproduce el fallo   ○ 2 corrección   ○ 3 documentación

El motor por debajo

bash · vía de respaldo
mem hcd start --kind fix --lane fast --title "Error de token en sidebar" --why "el panel queda vacío"
mem hcd show                         # unidad activa, paso y siguiente skill
mem hcd verify --task 1 --expect-fail -- 'go test ./pkg/installer -run TestToken'   # rojo
mem hcd verify --task 1 -- 'go test ./pkg/installer -run TestToken'                 # verde
mem hcd analyze                      # coherencia, sin escribir
mem hcd close --quote "aprobado"
Rojo antes del verde
Con --expect-fail registras que la prueba falla antes del cambio. Sin ese paso no hay demostración de que la prueba mida algo.
Evidencia que caduca
Si el código cambia después de verificar, la tarea pasa a ◌ en /tasks y hay que volver a ejecutarla.
Cierre citado
close exige tu aprobación literal con --quote. El agente no cierra por su cuenta.

Revisión independiente

Un segundo par de ojos que no ha visto la conversación.

Un modelo que revisa su propio trabajo en la misma sesión arrastra sus mismas suposiciones. pi-gomemory trae tres formas de revisión con distinto nivel de aislamiento.

splash_review

Es una herramienta de Pi que lanza una revisión en una sesión nueva, en memoria, sin historial, sin instrucciones del proyecto, sin skills ni extensiones. Solo tiene herramientas de lectura y no ve los servidores MCP. Recibe la ruta de un documento y, si quieres, una lente: seguridad, coherencia, alcance. Usa el modelo y la autenticación que tengas seleccionados en Pi, tiene un límite de cinco minutos y se puede cancelar.

en Pi
/reload    # una vez, después de instalar o actualizar
ejecuta splash_review sobre hcd/HCD-024.md con la lente "criterios de aceptación verificables"
Lo que Splash no hace

No aprueba nada ni registra decisiones HCD. La sesión principal lee el informe y decide. Un fallo de ejecución tampoco equivale a una revisión aprobada. La definición del rol vive en config/splash.md y no depende de Claude Code.

ACR y ADM

ACR · Revisión Adversarial por Consenso
Skill adversarial-consensus-review. Dos revisores independientes, un defecto se confirma solo por consenso, rondas de corrección acotadas y re-verificación. Las herramientas review_* de gomemory guardan cada paso.
ADM · Auditoría Defensiva Multilenguaje
Skill defensive-qa-audit. Busca fugas de credenciales, PII, recursos y errores expuestos en Go, TypeScript, Shell, SQL y CI. Cada hallazgo lleva evidencia reproducible y una propuesta de cierre.

Si escribes las siglas en el chat, Pi carga la skill correspondiente sin preguntar qué significan.

en Pi
haz un ACR del diff contra main
ADM sobre extensions/gomemory-tdd.ts

Una sesión de punta a punta

Un fix real, desde la terminal vacía hasta la unidad cerrada.

El ejemplo es pequeño a propósito. Lo que interesa es el orden: memoria primero, grafo después, prueba en rojo, cambio, prueba en verde, y lo aprendido guardado antes de salir.

  1. Abrir

    bash
    cd ~/proyectos/pi-gomemory
pi-gomemory

    el banner con versiones y, en el contexto, las decisiones recientes del proyecto.

  2. Recordar

    Pides: «¿qué sabemos del cálculo de cuotas?». Pi llama a search_memories y encuentra la decisión que fijó «nunca mostrar cifras aproximadas».

  3. Ubicar

    «¿Dónde se construye la barra de cuota y quién la llama?». Pi usa codegraph_explore y recibe el código de usage.go con sus llamadores, sin abrir carpetas a ciegas.

  4. Abrir la unidad

    /skill:hcd con la descripción del fallo. Vía rápida, tipo fix. /tasks muestra las tareas pendientes.

  5. Rojo, cambio, verde

    Pi escribe la prueba y la registra en rojo con --expect-fail. Aplica el cambio, lanza run_test_suite y registra la evidencia en verde. En el panel de /tdd ves avanzar cada test.

    las tareas aparecen como ✓ en /tasks.

  6. Revisar

    Para un cambio con riesgo, splash_review sobre el documento de la unidad, o un ACR del diff. Pi lee el informe y corrige lo confirmado.

  7. Cerrar y guardar

    Das la aprobación y Pi ejecuta mem hcd close --quote "…". Guarda el bug con su causa raíz con save_memory y termina con end_session, que deja un resumen para la próxima sesión.

La próxima vez que abras pi-gomemory en esa carpeta, el contexto incluirá la unidad cerrada, el bug y el resumen de la sesión. No hace falta volver a explicarle nada.

Actualizar, diagnosticar, desinstalar

Mantener el harness al día sin romper lo que ya funciona.

Actualizar

El launcher revisa siete componentes en cada arranque: pi-gomemory, pi, mem, codegraph, codebase-memory-mcp, pi-antigravity y pi-cc-extensions. Los dos plugins van fijados a la versión del catálogo oficial de Pi y solo cambian con una release nueva de pi-gomemory.

bash
pi-gomemory-setup version        # versión instalada
pi-gomemory-setup check-update   # ¿hay release nueva? (caché de 24 h)
pi-gomemory-setup deps-refresh   # consulta las últimas versiones
pi-gomemory-setup deps-status    # lo desactualizado; sale con código 10 si hay algo
pi-gomemory-setup deps-update    # actualiza cada componente con su comando oficial
pi-gomemory-setup update         # solo pi-gomemory: descarga, verifica SHA256SUMS y reinstala

Si el checksum no coincide, update rechaza la descarga y el binario actual no cambia. Después de actualizar, ejecuta /reload en Pi para cargar herramientas nuevas como splash_review.

Reinstalar por partes

ComandoQué rehace
pi-gomemory-setup mcpSolo las tres entradas de mcp.json
pi-gomemory-setup themeSolo el tema
pi-gomemory-setup pluginSolo pi-antigravity y pi-cc-extensions
pi-gomemory-setup skillsSolo el repositorio de skills
pi-gomemory-setup harnessSolo el launcher

Desinstalar

La desinstalación solo borra lo que puede demostrar que instaló. Compara la huella SHA256 de cada archivo con ~/.pi-gomemory/manifest.json; si editaste algo, lo conserva y lo lista como omitido.

bash
pi-gomemory-setup uninstall --dry-run         # qué se retiraría, sin tocar nada
pi-gomemory-setup uninstall                   # muestra el plan y pide confirmación
pi-gomemory-setup uninstall --yes --verbose   # sin preguntar, con log en ~/.pi-gomemory/uninstall.log
pi-gomemory-setup install                     # reinstalación limpia
Opciones
  • --packages quita también los dos plugins de npm.
  • --self borra el propio pi-gomemory-setup.
  • --yes es obligatorio sin terminal interactiva.
Lo que conserva
La memoria de gomemory (mem, su base de datos, .gomemory/ y hcd/), tus skills, otros servidores MCP y los binarios pi, mem, codegraph y codebase-memory-mcp.

Tras desinstalar queda la marca ~/.pi-gomemory/uninstalled, para que un launcher que siga en el sistema no reinstale skills al arrancar. install la retira.
