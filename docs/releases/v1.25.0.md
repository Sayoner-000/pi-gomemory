# v1.25.0: skills desde mem y codegraph como grafo principal

Cuando `mem` actualizaba una skill, Pi seguía usando la copia embebida en el binario hasta que alguien la actualizaba a mano en `pi-gomemory`. En esta versión, `SyncSkillRepo` lee primero las skills que `mem` ya instaló en el anfitrión, `doctor` avisa si alguna quedó desfasada y el protocolo de Pi prioriza `codegraph` como grafo principal (HCD-073).

## Qué cambia

### Skills desde `mem` y aviso en `doctor`
`installEmbeddedSkills` busca el `SKILL.md` vigente en `~/.claude/skills`, `~/.config/opencode/skills`, `~/.codex/skills` o `~/.gemini/config/skills` antes de usar el embebido. Si no hay copia de `mem`, usa la embebida; si el usuario editó una skill en `~/.pi-gomemory/skills`, esa edición se conserva.

`pi-gomemory-setup doctor` compara las skills de Pi con las de `mem` y muestra una advertencia con el nombre de las que difieren.

Se actualizan también las 6 copias embebidas que estaban desfasadas respecto a `mem`: `hcd`, `hcd-approve`, `hcd-define`, `hcd-verify`, `adversarial-consensus-review` y `defensive-qa-audit`.

### Ruta de Gemini
`hostSkillSources` apunta ahora a `~/.gemini/config/skills`, la ruta real donde `mem` instala sus skills para Antigravity/Gemini.

### Protocolo de impacto con `codegraph` primero
`gomemory-context.ts` y `gomemory-plan.ts` (`IMPACT_PROTOCOL`) piden consultar `codegraph` como grafo principal antes de editar o abrir un HCD, y acudir a `codebase-memory` solo cuando haya huecos de cobertura o trazas que `codegraph` no resuelva. La instrucción propia de Pi sobre una verificación por llamada Bash vive ahora en `gomemory-context.ts`, dejando `hcd-verify` idéntica a la de `mem`.

## Actualización

```bash
pi-gomemory-setup update
pi-gomemory-setup doctor
```

En Pi, abre una sesión nueva o ejecuta `/reload` para cargar el protocolo actualizado.
