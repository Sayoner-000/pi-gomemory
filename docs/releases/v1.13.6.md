# v1.13.6 — La configuración de Pi enlazada con symlinks sigue enlazada

Fecha: 2026-11-14.

## Cambios

Corrige H-02, el último hallazgo abierto de la [auditoría ACR/ADM del 2026-11-14](../audits/2026-11-14-acr-adm.md) ([HCD-036](../../hcd/HCD-036-las-configuraciones-de-pi-enlazadas-con.md)). Con v1.13.5, que corrigió H-01, H-03, H-04 y H-05, quedan cerrados los cinco.

Afecta a quien gestiona `~/.pi/agent/mcp.json`, `settings.json`, `AGENTS.md` o `pi-cc-extensions.json` con enlaces simbólicos, por ejemplo desde un repositorio de dotfiles.

- **Se escribe a través del enlace:** antes, cada escritura creaba un archivo temporal junto a la ruta y lo renombraba sobre ella, lo que sustituía el enlace por un archivo normal. Ahora:
  - `install`, `update`, `uninstall` y los subcomandos `mcp`, `theme`, `plugin` y `skills-sync` resuelven el enlace y escriben en el archivo de destino.
  - Vale para enlaces relativos y para cadenas de enlaces. El temporal se crea junto al archivo final, de modo que el reemplazo sigue siendo atómico aunque el destino esté en otro disco.
  - Se conservan los bits de permiso del destino.
  - El `skills-sync` que lanza el launcher en cada arranque ya no rompe el enlace de `settings.json`.
- **Un enlace que no apunta a un archivo se rechaza:** un enlace roto (por ejemplo, con el repositorio de dotfiles sin montar), un bucle o un enlace a un directorio dan el error `<ruta>: el enlace no apunta a un archivo (…); no se modifica`.
  - `install` aborta en ese paso.
  - `plugin` lo comprueba antes de ejecutar `pi install`.
  - No se toca ni el enlace ni la ruta a la que apunta. Antes, un enlace roto se sustituía en silencio por un archivo nuevo casi vacío.
  - Si el destino está en una carpeta sin permiso de escritura, también falla sin tocar nada.
- **`uninstall` nunca borra un enlace de configuración:**
  - Las entradas de pi-gomemory se retiran del archivo de destino.
  - Un `AGENTS.md` enlazado que se queda sin contenido se vacía en el destino, en lugar de borrar el enlace.
  - Un `pi-cc-extensions.json` enlazado se omite con un aviso visible: `[omitir] … — enlace a una configuración propia: se conserva`.
  - Un enlace que no apunta a un archivo aparece como `[fallido]` en el plan, o al aplicar si se rompió después de confirmar. El comando termina con error y el manifiesto se conserva, como desde v1.13.5.
  - `pi-cc-extensions.json` solo se comprueba con `--packages`, que es cuando `uninstall` lo toca.

`pi install` y `pi remove` ya conservaban el enlace: lo comprobamos con Pi 1.5.2 y no necesitan cambios. El launcher, el tema, las extensiones, las skills, las cachés y el manifiesto mantienen su comportamiento.

## Verificación

- `TestHCD036C01` a `TestHCD036C16` (y la guarda `TestHCD036C14`) en `pkg/installer/hcd036_symlink_test.go`. Todas las que cambian comportamiento se observaron primero en rojo, y la suite completa también, antes de tocar el código.
- Siguen pasando sin cambios las pruebas de HCD-027, HCD-032, HCD-034 y HCD-035.
- Comprobación con el binario real en un `HOME` temporal:
  - con los cuatro archivos enlazados a una carpeta de dotfiles, `install` y `uninstall --yes --packages` conservan los cuatro enlaces y los cambios llegan a los destinos;
  - con `mcp.json` enlazado a una ruta inexistente, `install` falla en el paso MCP con salida 1, el enlace queda igual y no se crea el destino.
- `go vet ./...`, `go test ./...` y `go test -race ./...` en verde.

## Actualizar

```sh
pi-gomemory-setup update
pi-gomemory-setup version
```

Si una versión anterior ya sustituyó alguno de tus enlaces, `update` no lo rehace: vuelve a crearlo a mano (por ejemplo, `ln -sf ~/dotfiles/pi/settings.json ~/.pi/agent/settings.json`), después de copiar al repositorio lo que quieras conservar del archivo actual.

## Límites

- El launcher ignora a propósito los errores de `skills-sync` para no impedir que Pi arranque. Con un `settings.json` roto, el error solo aparece al ejecutar `pi-gomemory-setup skills-sync` o `install` a mano.
- Queda una ventana de milisegundos entre resolver el enlace y renombrar el temporal; no se defiende contra otro proceso que cambie el enlace justo en ese momento.
- Solo se conservan los bits de permiso del destino, no el propietario, las ACL ni los atributos extendidos.
- Consulta [problemas conocidos](../known-issues.md).
