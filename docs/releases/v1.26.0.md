# v1.26.0: un catálogo de componentes, sync y la última release en install.sh

Hasta ahora `curl … install.sh | bash` instalaba la versión escrita en el script y solo traía las herramientas que faltaban: si ya tenías `pi` o `codegraph` en una versión vieja, seguían viejas después de instalar. La lista de herramientas estaba copiada en cuatro sitios y `herdr`, que usa el launcher, no estaba en ninguno. Esta versión junta todo en un catálogo, añade `sync` para dejar cada herramienta instalada y al día, y hace que `install.sh` descargue siempre la última release (HCD-076).

## Qué cambia

### `install.sh` instala la última release
Sin `PI_GOMEMORY_VERSION`, el script lee la etiqueta de la redirección de `releases/latest` y descarga ese binario, que sigue verificándose con `SHA256SUMS`. Ya no hay que subir una versión en el script con cada release. Para fijar una versión, exporta `PI_GOMEMORY_VERSION=vX.Y.Z`. Si la etiqueta no se puede resolver, el script se detiene y lo sugiere. Al compilar desde el código fuente no consulta la red.

### `sync`: instalar lo que falta y actualizar lo que está viejo
`pi-gomemory-setup sync` revisa `pi`, `mem`, `codegraph`, `codebase-memory-mcp` y `herdr`. Si una falta, la instala desde su canal oficial; si hay una versión más nueva, la actualiza con su propio comando (`pi update --self`, `mem update -y`, `codegraph upgrade`, `herdr update`, o el release verificado de codebase-memory-mcp). No pregunta herramienta por herramienta.

- Es el primer paso de `install`, en lugar de la comprobación anterior.
- `update` lo ejecuta una sola vez: dentro del `install` que relanza con una release nueva, o directamente si pi-gomemory ya está al día.
- `deps-update` pasa todas las herramientas desactualizadas a un único `sync`, así que ninguna se actualiza dos veces.
- Consulta la red aunque `PI_GOMEMORY_NO_UPDATE_CHECK` esté puesta, porque lo pides tú, y al terminar guarda en la caché las versiones que dejó instaladas.
- Solo es un error fatal no poder instalar `pi` o `mem` cuando faltan. Si falla la actualización de una herramienta que ya tenías, o cualquier paso de una opcional, avisa con el comando manual y sigue.
- Antes de instalar `pi` comprueba que haya Node.js 22.19 o superior y npm, y si faltan te dice cómo instalarlos sin lanzar el instalador de Pi.
- `--only=a,b` y `--skip=c` eligen las herramientas, `--yes` evita la lista y `--json` devuelve qué se hizo con cada una. `pi` y `mem` se tratan siempre.

### Lista para elegir en la terminal
Cuando hay terminal, `install` (también con `curl | bash`) y `sync` muestran antes de empezar una lista numerada con la versión instalada y la publicada de cada herramienta. Escribe los números que quieras marcar o desmarcar y pulsa Enter. Las opcionales vienen marcadas, salvo en modo lite.

### `herdr` como herramienta opcional
Se instala con `https://herdr.dev/install.sh` en tu directorio de binarios y se actualiza con `herdr update`. Aparece en `doctor`, en el aviso de actualizaciones y en lo que `uninstall` conserva.

### `/componentes` en Pi
Lista todos los componentes con su estado, deja marcar o desmarcar las herramientas opcionales y ejecuta `sync` con lo elegido. Si `pi` se actualizó, te pide reiniciar Pi.

### Un catálogo para todo
`pkg/installer/components.go` declara cada componente una vez. La instalación, `deps-status`, `deps-update`, `doctor`, `uninstall` y el nuevo `pi-gomemory-setup components --names | --json` salen de ahí. `doctor` marca una herramienta opcional ausente como aviso y ya no como fallo.

## Actualización

```bash
pi-gomemory-setup update
pi-gomemory-setup doctor
```

`update` termina ejecutando `sync`, así que también pone al día las herramientas e instala `herdr` si falta. Si no lo quieres, ejecuta después `pi-gomemory-setup sync --yes --skip=herdr` o desmárcalo en la lista. En Pi, ejecuta `/reload` para cargar `/componentes`.
