# v1.13.1 — Las releases nuevas se anuncian en menos de una hora

Fecha: 2026-11-13.

## Cambios

- **Consulta de versiones cada hora ([HCD-031](../../hcd/HCD-031-una-release-nueva-tarda-hasta-24-h-en-an.md)):** la comprobación de versiones del launcher y del pie de Pi solo volvía a la red si su última consulta tenía más de 24 h. Tras publicar v1.13.0, una consulta hecha 23 minutos antes ocultó el aviso. Ahora vuelve a la red como mucho una vez por hora, así que una release se anuncia como mucho una hora después de publicarse. Son unas 7 consultas por hora como máximo, lejos del límite de la API de GitHub sin autenticar.
- **Documentación:** las notas de v1.13.0, el README, la guía y `docs/` afirmaban que una release nueva aparecía «en la misma apertura». Ahora describen el comportamiento real.

## Verificación

- `TestHCD031DepsCacheTTL`, observado primero en rojo: una caché de 30 minutos se reutiliza y una de más de una hora vuelve a la red y anuncia la versión nueva.
- Reproducción real contra GitHub con un binario v1.12.1 y una caché de 90 minutos: el binario publicado de v1.13.0 no anuncia la release; el de esta versión sí.
- `TestH11HarnessTTLAndPromptCap` actualizado al nuevo plazo; `go vet ./...` y `go test -race ./...` en verde.

## Actualizar

```sh
pi-gomemory-setup update
pi-gomemory-setup version
```
