# v1.13.7 — `PI_GOMEMORY_NO_UPDATE_CHECK` significa lo mismo en todas partes

Fecha: 2026-11-14.

## Cambios

Unifica cómo se interpreta `PI_GOMEMORY_NO_UPDATE_CHECK` ([HCD-037](../../hcd/HCD-037-pi-gomemory-no-update-check-significa-lo.md)). Era el último punto pendiente que dejaron anotado las releases v1.13.5 y v1.13.6.

- **Una sola regla:** el binario (`check-update`), el launcher `pi-gomemory` y el aviso del pie de Pi aplican la misma regla:

  | Valor | Comprobación automática |
  |---|---|
  | sin definir, vacía, `0`, `false` (sin distinguir mayúsculas ni espacios) | **activa** |
  | cualquier otro: `1`, `yes`, `true`, `no`… | **desactivada** |

  Antes, el launcher y el pie la desactivaban con cualquier valor, así que `PI_GOMEMORY_NO_UPDATE_CHECK=0` o `=false` apagaban el aviso sin querer, mientras que `check-update` sí comprobaba.
- **`deps-refresh` respeta la variable:** con la comprobación desactivada no consulta la red ni reescribe `~/.pi/agent/pi-gomemory-deps.json`, y devuelve la última consulta tal como esté. Antes solo la filtraban el launcher y el pie, así que un `deps-refresh` ejecutado por otra vía (un alias o un cron) consultaba igual.
- **Sin cambios en `update` ni en `deps-update`:** los pides tú, así que siguen consultando siempre (desde v1.13.5).

El launcher usa una función de shell compatible con el bash 3.2 de macOS.

## Verificación

- `TestHCD037GoRule`, `TestHCD037Launcher`, `TestHCD037Footer` y `TestHCD037DepsRefresh` en `pkg/installer/hcd037_update_check_test.go`, con la misma tabla de 11 valores para Go, el launcher (el script real generado, ejecutado con `/bin/bash`) y el pie. Las que cambian comportamiento se observaron primero en rojo, y la suite completa también, antes de tocar el código.
- `TestHCD035C13`, `TestHCD035C14`, `TestCheckUpdateDisabled` y `TestHarnessDepsCheck` siguen pasando sin cambios.
- Comprobación con el binario real en un `HOME` temporal: `PI_GOMEMORY_NO_UPDATE_CHECK=1 pi-gomemory-setup deps-refresh` termina con 0 sin crear la caché; con `=0` consulta y la crea.
- `go vet ./...`, `go test ./...` y `go test -race ./...` en verde.

## Actualizar

```sh
pi-gomemory-setup update
pi-gomemory-setup version
```

Después ejecuta `/reload` en Pi para cargar el pie actualizado. Si tenías `PI_GOMEMORY_NO_UPDATE_CHECK=0` o `=false` para «no desactivar», a partir de ahora el aviso volverá a aparecer, que es lo que pretendías. Para desactivarlo, usa `=1`.
