### H-01 — Error MCP deja una conmutación parcial

- **Categoría:** Integridad / manejo de errores.
- **Severidad y estado:** Media, CONFIRMADO por reproducción y ambos revisores.
- **Ubicación:** `pkg/installer/codemode.go:21-32`, en particular escritura de settings en 25 antes de MCP en 32.
- **Ruta de alcance:** CLI `codemode on|off` → `runCodemode` → `SetCodemode` → `setCodemodeSettings` → `writeMCPServers`.
- **Análisis:** la atomicidad individual de cada JSON no proporciona atomicidad entre ambos archivos. MCP inválido, un enlace inválido o un fallo de escritura llega después de modificar settings. En off pueden quedar servidores expuestos por codemode sin la activación correspondiente en settings. El comando devuelve error, pero ya dejó cambios persistentes.
- **Evidencia:** `TestAudit114AtomicCodemode/on` y `/off` fallan porque settings cambia pese a MCP rechazado. El binario compilado reproduce on: exit 1 y `defaultTools` pasa de `["+grep"]` a `["+grep","+codemode"]`.
- **Cierre mínimo:** validar ambos destinos y estructuras antes de escribir; conservar instantánea y permisos del primer archivo para restaurarlo ante fallo de la segunda escritura. Comunicar también cualquier fallo de restauración. No prometer transacción frente a un corte del proceso sin un mecanismo adicional de recuperación.
- **Código defensivo propuesto, no aplicado:** sustitución de `SetCodemode`; requiere importar `errors`. Conserva la política existente respecto de escrituras concurrentes (no introduce bloqueo).

```go
func SetCodemode(piAgentDir string, enabled bool) error {
    if err := os.MkdirAll(piAgentDir, 0755); err != nil {
        return fmt.Errorf("crear %s: %w", piAgentDir, err)
    }
    settingsPath, err := configTarget(filepath.Join(piAgentDir, "settings.json"))
    if err != nil { return err }
    mcpPath, err := configTarget(filepath.Join(piAgentDir, "mcp.json"))
    if err != nil { return err }
    mcp, err := readJSONObject(mcpPath)
    if err != nil { return err }
    if raw, ok := mcp["mcpServers"]; ok {
        var servers map[string]json.RawMessage
        if err := json.Unmarshal(raw, &servers); err != nil || servers == nil {
            return fmt.Errorf("%s: mcpServers no es un objeto; no se modifica", mcpPath)
        }
    }
    before, err := os.ReadFile(settingsPath)
    existed := err == nil
    if err != nil && !errors.Is(err, os.ErrNotExist) { return err }
    mode, err := modeOrDefault(settingsPath, 0600)
    if err != nil { return err }
    if err := setCodemodeSettings(piAgentDir, enabled); err != nil { return err }
    servers := DefaultMCPServers()
    if enabled { servers = CodemodeMCPServers() }
    if err := writeMCPServers(piAgentDir, servers); err != nil {
        var restoreErr error
        if existed {
            restoreErr = writeFileAtomic(settingsPath, before, mode)
        } else {
            restoreErr = os.Remove(settingsPath)
            if errors.Is(restoreErr, os.ErrNotExist) { restoreErr = nil }
        }
        if restoreErr != nil {
            return errors.Join(err, fmt.Errorf("restaurar settings: %w", restoreErr))
        }
        return err
    }
    return nil
}
```

- **Validación del cierre:** ambos subcasos conservan bytes y permisos ante MCP inválido; añadir fallo controlado de segunda escritura, ausencia inicial de settings, enlaces válidos/inválidos y error de rollback. Mantener idempotencia y camino sano. La propuesta no se ha compilado ni aplicado como corrección en esta auditoría.

### H-02 — Uninstall desconoce el perfil híbrido propio

- **Categoría:** Ciclo de vida / integridad de configuración.
- **Severidad y estado:** Media, CONFIRMADO por reproducción y ambos revisores.
- **Ubicación:** `pkg/installer/uninstall.go:457-467` y revalidación de la acción MCP; `planSettings:579-658` no gestiona defaultTools.
- **Ruta de alcance:** `codemode on` crea el perfil → `uninstall --yes` → `BuildUninstallPlan` → `planMCP`.
- **Análisis:** solo compara contra `DefaultMCPServers()`. Gomemory y codebase-memory con `exposure: codemode` y toolExposure no coinciden y se conservan como personalizaciones, aun siendo exactamente el perfil generado por esta versión. Codegraph sí se retira. La salida final anuncia desinstalación correcta.
- **Evidencia:** `TestAudit114HybridUninstall`: `Uninstall` devuelve nil; resumen `1 retirados, 2 omitidos, 0 fallidos`; permanecen ambos servidores y `+codemode`.
- **Cierre mínimo:** reconocer las dos definiciones administradas exactas al planificar y revalidar al aplicar, sin borrar personalizaciones. La retirada de `+codemode` necesita procedencia o política explícita: no eliminarlo a ciegas porque también sirve para otras herramientas/MCP del usuario. El defecto confirmado de este hallazgo son los dos registros MCP propios, no una autorización para retirar herramientas ajenas.
- **Código defensivo propuesto, no aplicado:** sustituir el bloque que selecciona `want` dentro del bucle de `planMCP`; la acción existente debe seguir usando ese mismo `want` en su revalidación.

### H-03 — Éxito falso tras fallar el sondeo local

- **Categoría:** Éxito falso / errores silenciados.
- **Severidad y estado:** Media, CONFIRMADO en ADM; SUSPECT en ACR por identificación de un solo revisor.
- **Ubicación:** `pkg/installer/deps.go:415-440`, consumido en `RunDepsUpdate:462-495`.
- **Ruta de alcance:** `deps-update` → `RunDepsUpdate` → `effectiveDepState` → `liveVersion` → probe Current.
- **Análisis:** `liveVersion` convierte el error en cadena vacía; `effectiveDepState` mantiene Current y Error antiguos de la caché. Si la caché decía current=latest, el comando devuelve 0 y anuncia «están al día» aunque acabe de fallar la lectura actual. El fallback de caché está documentado para el aviso `DepsStatusFor`; no se propone eliminar esa política sin distinguir el comando que asegura éxito.
- **Evidencia:** `TestAudit114CurrentProbeFailure`, caché mem 1.0.0/1.0.0 y probe con `SYNTH-PROBE-FAILURE`: `calls=1 exit=0 stdout="✓ El meta-harness y sus dependencias están al día.\n" stderr=""`.
- **Relación con cierres previos:** HCD-041/042 cubren cachés ausentes/incompletas y versiones no comparables; esta variante pierde el error del nuevo sondeo. No se afirma que hayan reaparecido los mismos escenarios ya cerrados.
- **Cierre mínimo:** lectura estricta para deps-update, reteniendo el error como estado desconocido; no cambiar implícitamente el fallback del aviso de arranque. Mensaje genérico sin volcar salida potencialmente sensible del probe.
- **Código defensivo propuesto, no aplicado:** añadir este helper y usarlo en lugar de `effectiveDepState` solo dentro de `RunDepsUpdate`. Mantiene el error anterior de caché, si existe, hasta refrescarla.

```go
func effectiveDepStateForUpdate(d DepState, p DepProbe) DepState {
    d.Update, d.Manual = p.Update, p.Manual
    for _, pin := range PinnedPackages() {
        if d.Name == pin.Name { d.Latest = pin.Version; break }
    }
    if p.Current == nil {
        d.Current, d.Error = "", "sin lector de versión instalada"
        return d
    }
    ctx, cancel := context.WithTimeout(context.Background(), liveVersionTimeout)
    defer cancel()
    cur, err := p.Current(ctx)
    if err != nil {
        d.Current, d.Error = "", "no se pudo comprobar la versión instalada"
        return d
    }
    d.Current = cur
    return d
}
```

- **Validación del cierre:** el reproductor sale 1 y no anuncia al día; cubrir timeout, lectura vacía, paquete borrado después de refrescar caché, actualización parcial conocida y precedencia del pin. El código propuesto no se aplicó ni verificó como cierre.

### H-04 — Selección absoluta se anuncia como híbrida

- **Categoría:** Compatibilidad / contrato de herramientas.
- **Severidad y estado:** Media provisional, SOSPECHOSO. Comportamiento reproducido, interpretación contractual pendiente.
- **Ubicación:** `pkg/installer/codemode.go:71-73,96-113`.
- **Ruta de alcance:** settings preexistente con `defaultTools:["codemode"]` → `codemode on|status`.
- **Observación:** conserva la selección absoluta y status informa Enabled=true. El reproductor demuestra ese resultado, no que deban restaurarse herramientas retiradas deliberadamente por el usuario.
- **Contrato externo comprobado:** documentación instalada de Pi 1.5.2, `docs/settings.md:42-56`: los nombres planos reemplazan herramientas base; `+codemode` es aditivo. Esto NO es el campo `codemode.mode:"only"`: son mecanismos distintos. No atribuir al instalador una escritura de ese campo, que no realiza.
- **Evidencia:** `TestAudit114AbsoluteToolSelection` falla la expectativa aditiva: settings conserva `["codemode"]` y status indica on. Solo A lo identificó.
- **Propuesta de cierre:** aclarar si «híbrido» garantiza herramientas base o preserva toda selección explícita. En el segundo caso, documentarlo e informar selección restringida en status; en el primero, acordar una normalización que no destruya la selección del usuario.
- **Código corregido:** no se prescribe un cambio de selección listo para producción hasta resolver esa decisión; convertir automáticamente `codemode` a `+codemode` podría contradecir la intención explícita previa.
- **Validación futura:** casos `["codemode"]`, `["read","codemode"]`, listas aditivas y desactivaciones explícitas; comprobar herramientas efectivamente ofrecidas por Pi, no solo el booleano del instalador.
