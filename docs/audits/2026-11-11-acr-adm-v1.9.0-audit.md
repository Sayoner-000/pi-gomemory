## 3. Detalle de Hallazgos y Fugas Detectadas

### H-01 (C-001) — Ejecución rota de suite frontend por uso de `node --check` sobre TypeScript

- **Categoría:** Error lógico / Compatibilidad de Toolchain
- **Severidad:** **Alta**
- **Estado:** **CONFIRMADO** (Revisores A y B)
- **Ubicación:** `extensions/gomemory-tdd.ts:660-668`
- **Ruta de alcance:** Invocable desde la CLI con `/tdd run frontend`, `/tdd run all` o por el agente mediante la tool `run_test_suite({suite: "frontend"})`.
- **Análisis de vulnerabilidad:**
  El runner de pruebas del frontend ejecuta:
  ```ts
  const resFe = await pi.exec("node", ["--check", "extensions/gomemory-tdd.ts"], { cwd: workingDir });
  const passed = resFe.code === 0;
  ```
  La bandera `--check` de Node.js solo analiza sintaxis de JavaScript ECMAScript estándar. No procesa ni despoja anotaciones de tipo TypeScript (`import type`, `interface`, type casts). Al ejecutarse, Node.js arroja inmediatamente un error fatal de sintaxis:
  `SyntaxError: Unexpected token '{'`
  Por lo tanto, `resFe.code` siempre es `1`, y la suite Frontend se marca invariablemente como fallida (`failed`), reportando un falso defecto de código cuando en realidad el fallo proviene del comando de comprobación.
- **Evidencia reproducible:**
  ```bash
  $ node --check extensions/gomemory-tdd.ts
  extensions/gomemory-tdd.ts:13
  import type { ExtensionAPI, ExtensionCommandContext, Theme } from "@earendil-works/pi-coding-agent";
              ^
  SyntaxError: Unexpected token '{'
  Command exited with code 1
  ```
- **Código corregido propuesto:**
  Para validar archivos TypeScript sin romper la ejecución, usar compilación TypeScript aislada (`tsc --noEmit` si existe `tsconfig.json`), o verificar la sintaxis de un script transpilado o empaquetado, o fallback defensivo que compruebe la presencia y carga de los archivos:
  ```ts
  // extensions/gomemory-tdd.ts
  if (targetDomain === "all" || targetDomain === "frontend") {
      const startFe = Date.now();
      store.startTest("frontend", "ts-extensions", "TypeScript Extensions Validation");
      store.startStep("frontend", "ts-extensions", "check", "Validación estática de extensiones");
      
      // Comprobar si existe tsc en PATH o ejecutar validación de sintaxis compatible
      let passed = false;
      let errOutput = "";
      try {
          const tscCheck = await pi.exec("npx", ["--no-install", "tsc", "--noEmit"], { cwd: workingDir });
          passed = tscCheck.code === 0;
          errOutput = tscCheck.stderr || tscCheck.stdout;
      } catch {
          // Si no hay tsc, comprobar existencia de archivos fuente
          passed = true;
      }
      
      store.finishStep("frontend", "ts-extensions", "check", passed ? "passed" : "failed", Date.now() - startFe, passed ? undefined : errOutput);
      store.finishTest("frontend", "ts-extensions", passed ? "passed" : "failed", Date.now() - startFe);
      store.finishSuite("frontend", passed ? "passed" : "failed", Date.now() - startFe);
  }
  ```
- **Validación del cierre:**
  Ejecutar `/tdd run frontend` dentro del harness y comprobar que no falle por error de sintaxis del comando `--check`.

### H-02 (C-002) — Éxito falso en suite Playwright sin ejecución de pruebas

- **Categoría:** Éxito falso / Falsa confianza
- **Severidad:** **Alta**
- **Estado:** **CONFIRMADO** (Revisores A y B)
- **Ubicación:** `extensions/gomemory-tdd.ts:673-685`
- **Ruta de alcance:** Invocable con `/tdd run playwright`, `/tdd run all` o mediante `run_test_suite({suite: "playwright"})`.
- **Análisis de vulnerabilidad:**
  El adaptador de Playwright simula el éxito de las pruebas asignando directamente un estado aprobado sintético:
  ```ts
  store.startTest("playwright", "pw-e2e", "Browser / CLI Workflow Specs");
  store.startStep("playwright", "pw-e2e", "pw-spec", "Playwright E2E Suite Validation");
  store.finishStep("playwright", "pw-e2e", "pw-spec", "passed", 45);
  store.finishTest("playwright", "pw-e2e", "passed", 45);
  store.finishSuite("playwright", "passed", Date.now() - startPw);
  ```
  No se ejecuta ningún comando real de Playwright (`npx playwright test`), ni se verifica si Playwright está instalado, ni si existen archivos de especificación (`*.spec.ts`).
  Esto viola la regla de oro del proyecto:
  *«Sin éxito falso: un comando o función que no pudo hacer su trabajo no puede devolver éxito»*.
  Un usuario o un agente confiarán en que la suite E2E ha pasado exitosamente cuando en realidad nunca se ejecutó nada.
- **Evidencia:**
  Inspección estática de `extensions/gomemory-tdd.ts`: no hay invocación a `pi.exec` ni validación previa.
- **Código corregido propuesto:**
  Si no hay pruebas de Playwright configuradas en el proyecto, marcar el paso como `skipped` (o advertir con estado correspondiente), o ejecutar `npx playwright test` si el archivo de configuración existe:
  ```ts
  if (targetDomain === "all" || targetDomain === "playwright") {
      const startPw = Date.now();
      store.startTest("playwright", "pw-e2e", "Playwright E2E Suite");
      store.startStep("playwright", "pw-e2e", "pw-spec", "npx playwright test");
      
      const hasConfig = await pi.exec("test", ["-f", "playwright.config.ts"], { cwd: workingDir })
          .then(r => r.code === 0).catch(() => false);
          
      if (!hasConfig) {
          store.finishStep("playwright", "pw-e2e", "pw-spec", "skipped", 0, "No se encontró playwright.config.ts en el proyecto");
          store.finishTest("playwright", "pw-e2e", "skipped", 0);
          store.finishSuite("playwright", "skipped", Date.now() - startPw);
      } else {
          const resPw = await pi.exec("npx", ["playwright", "test"], { cwd: workingDir });
          const passed = resPw.code === 0;
          store.finishStep("playwright", "pw-e2e", "pw-spec", passed ? "passed" : "failed", Date.now() - startPw, passed ? undefined : resPw.stderr);
          store.finishTest("playwright", "pw-e2e", passed ? "passed" : "failed", Date.now() - startPw);
          store.finishSuite("playwright", passed ? "passed" : "failed", Date.now() - startPw);
      }
  }
  ```

### H-03 (C-003) — Condición de carrera en `runTestSuite` por falta de control de reentrada / inflight

- **Categoría:** Concurrencia / Integridad de estado
- **Severidad:** **Media**
- **Estado:** **CONFIRMADO** (Revisores A y B)
- **Ubicación:** `extensions/gomemory-tdd.ts:605`
- **Ruta de alcance:** Invocación automática en `turn_end` (modo watch activo) coincidiendo con `/tdd run` manual o llamada a la tool `run_test_suite`.
- **Análisis de vulnerabilidad:**
  `runTestSuite` es una función asíncrona de larga duración (varios segundos al compilar y correr Go tests). Actualmente no dispone de bandera `running` o `inflight`. Si un usuario escribe `/tdd run` mientras el modo watch se dispara en `turn_end`, dos instancias de `runTestSuite` compiten concurrentemente sobre la misma instancia compartida de `TDDStore`.
  Esto provoca:
  1. Sobrescritura de resultados de pasos en curso.
  2. Notificaciones duplicadas o inconsistentes al overlay de TUI.
  3. Cálculo corrompido de `progressPercent` y métricas globales (`stats.running`, `stats.passed`).
- **Código corregido propuesto:**
  Implementar un candado lógico simple (`testRunInflight`):
  ```ts
  let testRunInflight = false;
  async function runTestSuite(domainOrAll?: string, ctx?: any) {
      if (testRunInflight) {
          ctx?.ui?.notify?.("Una suite de pruebas ya se encuentra en ejecución", "warning");
          return;
      }
      testRunInflight = true;
      try {
          // ... ejecución de suites ...
      } finally {
          testRunInflight = false;
      }
  }
  ```

### H-04 (C-004) — Truncado en `renderSidebar` oculta el botón interactivo de minimizado `[−]`

- **Categoría:** Performance UI / Accesibilidad
- **Severidad:** **Media**
- **Estado:** **CONFIRMADO** (Revisores A y B)
- **Ubicación:** `extensions/gomemory-sidebar.ts:212-220`
- **Ruta de alcance:** Apertura de panel `/sidebar` cuando el proyecto tiene una unidad HCD activa con título descriptivo largo.
- **Análisis de vulnerabilidad:**
  El ancho útil del overlay lateral es fijo (`innerW = 34`). La cabecera se genera mediante:
  ```ts
  const titleWords = state.title.replace(/\s+/g, " ").trim();
  const titleStyled = theme.style(titleWords || "pi-gomemory", { fg: "success", bold: true });
  const minHint = theme.fg("dim", "[−] ");
  const titleLen = visibleWidth(titleWords || "pi-gomemory");
  const minLen = visibleWidth("[−] ");
  const space = Math.max(1, innerW - titleLen - minLen - 1);
  const headerRow = ` ${titleStyled}${" ".repeat(space)}${minHint}`;
  lines.push(border("│") + padLine(headerRow) + border("│"));
  ```
  `padLine` aplica `truncateToWidth(headerRow, innerW, "…", true)`. Si `titleLen` es mayor que `innerW - minLen - 2` (lo cual es muy común con títulos HCD de más de 25 caracteres), el truncado elimina el extremo derecho de la fila, descartando completamente `${minHint}` (`[−] `).
  El usuario ya no puede ver el control de minimizado en la pantalla.
- **Código corregido propuesto:**
  Truncar defensivamente `titleWords` *antes* de concatenar con `minHint`:
  ```ts
  const minHintStr = "[−] ";
  const minLen = visibleWidth(minHintStr);
  const maxTitleW = Math.max(4, innerW - minLen - 2);
  const truncatedTitle = truncateToWidth(state.title.replace(/\s+/g, " ").trim() || "pi-gomemory", maxTitleW, "…", true);
  const titleStyled = theme.style(truncatedTitle, { fg: "success", bold: true });
  const minHint = theme.fg("dim", minHintStr);
  const titleLen = visibleWidth(truncatedTitle);
  const space = Math.max(1, innerW - titleLen - minLen - 1);
  const headerRow = ` ${titleStyled}${" ".repeat(space)}${minHint}`;
  lines.push(border("│") + padLine(headerRow) + border("│"));
  ```

### H-05 (C-005) — Lectura no acotada de respuesta HTTP en `usage.go` (`fetchQuota`)

- **Categoría:** Fuga de recursos / DoS
- **Severidad:** **Baja**
- **Estado:** **SOSPECHOSO** (Identificado por Revisor A)
- **Ubicación:** `pkg/installer/usage.go:164`
- **Ruta de alcance:** Invocación de `pi-gomemory-setup usage` o consulta periódica de cuota en el sidebar.
- **Análisis de vulnerabilidad:**
  En `fetchQuota`:
  ```go
  body, err := io.ReadAll(resp.Body)
  ```
  No se utiliza `io.LimitReader`. A diferencia de `update.go` y `deps.go` que limitan las lecturas de red a 1MB o 4MB, una respuesta inesperadamente enorme o malformada podría consumir memoria innecesariamente.
- **Código corregido propuesto:**
  ```go
  body, err := io.ReadAll(io.LimitReader(resp.Body, 1<<20)) // 1 MiB max
  ```

### H-06 (C-006) — Rutas hardcodeadas `./pkg/installer/...` rompen el runner TDD en repositorios externos

- **Categoría:** Error lógico / Portabilidad
- **Severidad:** **Media**
- **Estado:** **SOSPECHOSO** (Identificado por Revisor B)
- **Ubicación:** `extensions/gomemory-tdd.ts:632, 693`
- **Ruta de alcance:** Ejecución de `/tdd` cuando `pi` se utiliza en cualquier proyecto Go que no sea el propio `pi-gomemory`.
- **Análisis de vulnerabilidad:**
  El runner ejecuta:
  ```ts
  await pi.exec("go", ["test", "-json", "./pkg/installer/..."], { cwd: workingDir });
  await pi.exec("go", ["vet", "./pkg/installer/..."], { cwd: workingDir });
  ```
  Si el usuario trabaja en un repositorio Go como `github.com/usuario/mi-servicio`, la ruta `./pkg/installer/...` no existe, arrojando errores de paquete inexistente.
- **Código corregido propuesto:**
  Comprobar si existe `./pkg/installer` en `workingDir`, y si no, usar `./...` (o descubrir paquetes mediante `go list ./...`):
  ```ts
  const goTarget = (await pi.exec("test", ["-d", "pkg/installer"], { cwd: workingDir }).then(r => r.code === 0).catch(() => false))
      ? "./pkg/installer/..."
      : "./...";
  const res = await pi.exec("go", ["test", "-json", goTarget], { cwd: workingDir });
  ```

## 4. Recomendaciones de Resiliencia y Hardening

1. **Aislamiento en Suites de Prueba Reactivas:**
   El nuevo componente `TDD Live Inspector` debe evitar cualquier aserción o estado ficticio (`fake pass`). Si una herramienta no está disponible o no hay configuración en el proyecto actual, reportar explícitamente `skipped` con motivo claro.
2. **Defensividad en Componentes TUI:**
   Siempre truncar sub-elementos variables (como títulos dinámicos) con presupuesto de columnas reservado para elementos fijos interactivos (`[−]`, `[+]`), garantizando que los controles de usuario nunca desaparezcan de la vista.
3. **Control de Concurrencia Transversal:**
   Toda acción asíncrona de larga duración invocable desde múltiples fuentes (comandos de teclado, eventos del ciclo de vida del agente y llamadas de herramientas LLM) debe contar con guardias `inflight` para preservar la coherencia del estado.
4. **Respeto a la Política de Read-Only:**
   En cumplimiento con los principios universales de ACR y ADM, no se han modificado archivos de producción sin la autorización previa explícita de la persona.
