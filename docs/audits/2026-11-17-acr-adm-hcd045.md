### H45-01 — El fixture «histórico» no coincide con el protocolo publicado

- **Categoría:** Compatibilidad / migración / diagnóstico.
- **Severidad y estado:** Media, CONFIRMADO por reproducción externa.
- **Ubicación:** `pkg/installer/instructions.go:13-57` (`legacyPiInstructions`), `uninstall.go:496-529` (`stripInstructions` e `instructionsBlock`), tests `hcd045_install_test.go:12-25`.
- **Ruta:** install → retireLegacyStep → RetireLegacyInstructions → stripInstructions; doctor usa instructionsBlock para la misma detección.
- **Causa:** la constante histórica quedó congelada después de ampliar la lista de tools y añadir el párrafo codemode de HCD-044. No coincide con `GomemoryPiInstructions` realmente publicado en HEAD. El detector sin marcadores exige coincidencia literal.
- **Efecto:** un AGENTS con el protocolo anterior sin marcas devuelve `retired=false, err=nil`, mantiene instrucciones obsoletas y tampoco será detectado por el mismo reconocedor del doctor. El formato marcado no necesita esa coincidencia y no presenta este caso.
- **Evidencia:** se extrajo la constante exacta con `git show 49cbbe9:pkg/installer/instructions.go`, sin cambiarla. [Fixture histórico](2026-11-17-acr-adm-hcd045-legacy-fixture.txt). El [reproductor](2026-11-17-acr-adm-hcd045-repro_test.go.txt) añade texto sintético propio antes/después y observa `retired=false err=<nil> legacyRemaining=true userPreserved=true`.
- **Por qué los tests pasan:** construyen el «formato antiguo» con la nueva constante y calculan want mediante el mismo stripInstructions que se evalúa. No son evidencia de compatibilidad con el upstream histórico.
- **Cierre mínimo:** mantener variantes históricas exactas e inmutables y reconocerlas tanto al retirar como al diagnosticar. No borrar por un título o prefijo genérico, porque podría abarcar texto propio.
- **Código defensivo propuesto:** helper de coincidencia exacta para integrar con las variantes históricas verificadas; no aplicado ni validado como corrección.

```go
func stripKnownLegacy(content string, known []string) (string, bool) {
    for _, protocol := range known {
        if protocol == "" { continue }
        i := strings.Index(content, protocol)
        if i < 0 { continue }
        before := content[:i]
        after := strings.TrimPrefix(content[i+len(protocol):], "\n")
        if strings.TrimSpace(after) == "" {
            before = strings.TrimRight(before, "\n")
            if before != "" { before += "\n" }
        }
        return before + after, true
    }
    return content, false
}
```

- **Validación del cierre:** usar el fixture publicado literal, no la constante vigente, con bloque en medio/al final/solo, archivo normal y symlink; conservar texto ajeno y permisos; verificar doctor antes/después e idempotencia. Incluir variantes históricas realmente distribuidas, no aceptar una aproximación por título.

### H45-02 — La barrera /plan se activa después de esperar

- **Categoría:** Concurrencia / control de modificaciones.
- **Severidad y estado:** Media, CONFIRMADO por dos análisis independientes y harness dinámico. PREEXISTENTE: el orden ya está en `49cbbe9:extensions/gomemory-plan.ts`; no es regresión atribuible a HCD-045.
- **Ubicación:** `extensions/gomemory-plan.ts:77-80,95-96,101-107`.
- **Ruta:** usuario ejecuta `/plan <texto>` durante una ejecución ocupada → loadMethod pendiente → tool_call write antes de setActive(true).
- **Evidencia:** promesa de `pi.exec` controlada en harness; mientras no se resuelve, write devuelve sin bloqueo: `plan_loading_write_blocked=false`. No se escribió un archivo real.
- **Cierre mínimo:** activar la barrera sincrónicamente antes de la carga y usar FALLBACK mientras tanto. Usar generación/identidad para no restaurar estado de una activación cancelada o de otra sesión.
- **Código defensivo propuesto:** patrón para las ramas de activación; requiere contador `generation` en el cierre y su invalidación al apagar/cambiar sesión. No aplicado.

```typescript
const activation = ++generation;
method = FALLBACK;
setActive(ctx, true);
const loaded = await loadMethod(ctx.cwd);
if (!active || activation !== generation) return;
method = loaded;
```

- **Validación del cierre:** durante una carga diferida write/edit y bash modificador ya se bloquean; lectura sigue; cancelación y activaciones consecutivas no reutilizan cargas viejas. El harness prueba la lógica del interceptor, no un calendario de concurrencia extremo a extremo del runtime Pi.

### O45-01 — Presupuesto y aviso de recorte

- **Ubicación:** `extensions/gomemory-context.ts:73-79`.
- **Observación:** se reservan 24576 bytes para el texto y luego se añaden newline + aviso. Con ASCII grande, la parte anterior al bloque Pi suma 24634 bytes. No se parten caracteres UTF8.
- **Estado:** informativa, no defecto bloqueante confirmado: el criterio puede significar «24576 bytes de texto original más aviso». Los tests actuales descuentan el aviso explícitamente. Aclarar la interpretación en lugar de inflar un exceso de 58 bytes.
- **Si el límite debe incluir el aviso:** reservar `Buffer.byteLength("\n" + TRUNCATION_LINE, "utf8")` antes de truncar entradas grandes. Validar tamaño del cuerpo emitido, no solo del texto retenido.

### S45-01 — /plan heredado entre sesiones

- **Ubicación:** `extensions/gomemory-plan.ts:41-43,101-119`.
- **Observación:** active/method residen en el cierre y no hay session_start que los reinicie. El harness activa /plan, dispara session_start(new) y sigue bloqueando write: `new_session_inherits_plan_block=true`.
- **Estado:** SOSPECHOSO como defecto: falta una política que determine si esa persistencia es intencionada. Es preexistente y no se debe corregir automáticamente.
- **Cierre propuesto:** acordar persistir o reiniciar; si se reinicia, invalidar cargas y limpiar estado e indicador visual por sesión. Comprobar new/resume/fork/reload con Pi real.
