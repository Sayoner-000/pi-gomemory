## 3. Detalle de Hallazgos y Análisis Defensivo

### H-01 (C-001) — `planAgents` en desinstalador reescribe `AGENTS.md` con permisos fijos `0644`

- **Categoría:** Permisos y Confidencialidad / Mínimo Privilegio
- **Severidad:** **Baja**
- **Estado:** **CONFIRMADO** (Revisores A y B)
- **Ubicación:** `pkg/installer/uninstall.go:273` (función `planAgents`)
- **Ruta de alcance:** Invocable mediante `pi-gomemory-setup uninstall` (o con banderas `--yes`/`--dry-run`).
- **Análisis de vulnerabilidad:**
  En `pkg/installer/uninstall.go`:
  ```go
  p.add(ActionRemove, path+" › bloque pi-gomemory", "protocolo escrito por pi-gomemory", func() error {
      cur, err := os.ReadFile(path)
      if err != nil {
          return err
      }
      out, _ := stripInstructions(string(cur))
      if strings.TrimSpace(out) == "" {
          return os.Remove(path)
      }
      return writeFileAtomic(path, []byte(out), 0644)
  })
  ```
  A diferencia de `writeJSONObject` (que fue endurecido en HCD-027 para consultar `os.Stat(path).Mode().Perm()` y no ampliar permisos existentes), `planAgents` invoca `writeFileAtomic` con `0644` hardcodeado. Si el usuario configuró `~/.pi/agent/AGENTS.md` con modo restringido `0600`, una desinstalación que limpie el bloque de instrucciones ampliaría los permisos a `0644`.
- **Código corregido propuesto:**
  ```go
  p.add(ActionRemove, path+" › bloque pi-gomemory", "protocolo escrito por pi-gomemory", func() error {
      cur, err := os.ReadFile(path)
      if err != nil {
          return err
      }
      out, _ := stripInstructions(string(cur))
      if strings.TrimSpace(out) == "" {
          return os.Remove(path)
      }
      perm := os.FileMode(0644)
      if info, err := os.Stat(path); err == nil {
          perm = info.Mode().Perm()
      }
      return writeFileAtomic(path, []byte(out), perm)
  })
  ```
- **Validación del cierre:** Test en `pkg/installer/` que cree `AGENTS.md` con modo `0600`, aplique el plan de desinstalación y compruebe que el modo final conserva `0600`.

### H-02 (C-002) — `httpJSON` en `deps.go` delega exclusivamente en el contexto sin timeout a nivel de cliente

- **Categoría:** Gestión de Recursos y Resiliencia
- **Severidad:** **Baja**
- **Estado:** **SOSPECHOSO** (Revisor A)
- **Ubicación:** `pkg/installer/deps.go:138` (función `httpJSON`)
- **Ruta de alcance:** Invocable vía `pi-gomemory-setup deps-refresh` o durante el chequeo periódico de dependencias.
- **Análisis de vulnerabilidad:**
  `httpJSON` usa `http.DefaultClient.Do(req)`. En `RefreshDeps`, `ctx` se crea con `depsProbeTimeout` (20 segundos), lo cual cancela la petición si se excede el plazo. Sin embargo, defensivamente es una buena práctica que los clientes HTTP posean su propio timeout de transporte o cliente estructurado (como se hace en `anthropic_usage.go` y `codex_usage.go` con `(&http.Client{Timeout: 10 * time.Second})`) para evitar que invocaciones futuras con contextos abiertos puedan quedar bloqueadas indefinidamente ante conexiones TCP colgadas.
- **Código corregido propuesto:**
  ```go
  var depsHTTPClient = &http.Client{Timeout: depsProbeTimeout}

  func httpJSON(ctx context.Context, url string, dst any) error {
      req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
      if err != nil {
          return err
      }
      req.Header.Set("User-Agent", "pi-gomemory-setup")
      resp, err := depsHTTPClient.Do(req)
      ...
  ```
- **Validación del cierre:** Prueba unitaria con servidor de prueba que verifique la expiración por timeout del cliente.
